# پله — پروژهٔ اندروید

این پروژه، فایل HTML اصلی برنامهٔ «پله» را داخل اپ قرار می‌دهد و با Android WebView اجرا می‌کند.

## امکانات نگه‌داشته‌شده
- فرم‌ها و محاسبات فاکتور، پیش‌فاکتور، خرید و برگشت
- طرف حساب‌ها و ورود مخاطب از فایل vCard/CSV
- دریافت و پرداخت، معین حساب، انبار و بایگانی
- تنظیمات، قفل برنامه، پشتیبان‌گیری و بازیابی JSON
- نگهداری داده‌ها در localStorage روی همان دستگاه
- انتخاب فایل از گوشی، چاپ/PDF از WebView، ذخیرهٔ تصویر در گالری و اشتراک تصویر

## ساخت APK
1. Android Studio را نصب کنید و Android SDK Platform 35 را دریافت کنید.
2. پوشهٔ `pelleh-android` را در Android Studio باز کنید.
3. منتظر بمانید Gradle Sync کامل شود.
4. از منوی **Build > Build Bundle(s) / APK(s) > Build APK(s)** خروجی بگیرید.
5. APK معمولاً در `app/build/outputs/apk/debug/app-debug.apk` قرار می‌گیرد.

## نکات مهم
- شناسهٔ برنامه: `ir.noorelectric.pelleh`، نام نمایشی: «پله».
- اطلاعات اصلی در حافظهٔ محلی اپ ذخیره می‌شود؛ پاک‌کردن داده‌های اپ یا حذف اپ ممکن است اطلاعات را حذف کند. پشتیبان JSON را مرتب خارج از گوشی نگه دارید.
- پشتیبان ابری مبتنی بر `claude.ai` در اپ مستقل وجود ندارد.
- فونت Vazirmatn و کتابخانهٔ html2canvas در HTML اصلی از CDN بارگیری می‌شوند؛ برای بارگیری آن‌ها اینترنت لازم است. در صورت نبود اینترنت، فونت جایگزین نمایش داده می‌شود و تولید تصویر فاکتور ممکن است کار نکند.
- دسترسی مستقیم به مخاطبین با API وب اصلی تضمین‌شده نیست؛ مسیر واردکردن vCard/CSV حفظ شده است.
- این محیط فاقد Android SDK و Gradle اجرایی است؛ بنابراین APK در اینجا کامپایل یا روی دستگاه واقعی آزمایش نشده است.

## ساخت APK با GitHub (بدون نصب Android Studio)
1. در GitHub یک Repository جدید بسازید.
2. تمام محتویات این پوشه را در مخزن آپلود کنید؛ پوشهٔ مخفی `.github` نیز باید آپلود شود.
3. وارد زبانهٔ **Actions** شوید و Workflow با نام **Build Android APK** را باز کنید.
4. روی **Run workflow** بزنید. با هر Push به شاخهٔ `main` نیز ساخت به‌صورت خودکار اجرا می‌شود.
5. پس از موفقیت اجرا، پایین صفحه در بخش **Artifacts** فایل `Pelleh-debug-apk` را دانلود کنید.
6. فایل ZIP دانلودشده را باز کنید و `app-debug.apk` را به گوشی منتقل و نصب کنید.

این خروجی نسخهٔ آزمایشی (debug) است؛ برای انتشار عمومی در فروشگاه‌ها باید نسخهٔ release امضاشده ساخته شود.
